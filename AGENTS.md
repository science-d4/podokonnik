# Repository Guidelines

Подоконник (Podokonnik) — нативное приложение для Apple Silicon и macOS 14+. Стек: Swift, AppKit, Metal и SpriteKit. Сборка использует Apple Command Line Tools и macOS SDK. Сторонних зависимостей нет.

## Структура проекта

- `Sources/SnowCore/` — физика снега, настройки, расписание трактора и управление частотой кадров.
- `Sources/Podokonnik/` — приложение, интерфейс, геометрия рабочего стола и рендеринг.
- `Tests/` — тестовые программы, графические фикстуры и бенчмарки.
- `Scripts/` — сборка, проверки, упаковка; `GenerateIcon.swift` создаёт иконку.
- `Resources/` — `Info.plist` и инструкция установки.
- `docs/` — спецификация, архитектура и ограничения проверок.
- `.build/` и `dist/` — игнорируемые Git результаты сборки и поставки.

Перед изменением поведения прочитайте `docs/spec.md`; устройство модулей описано в `docs/architecture.md`, ограничения проверок — в `docs/verification.md`. Временные результаты сохраняйте в `.build/`.

## Сборка и локальный запуск

Выполняйте команды из корня репозитория:

```sh
bash Scripts/build.sh                  # Собрать dist/Podokonnik.app
open dist/Podokonnik.app                # Запустить приложение
bash Scripts/test.sh                   # Выполнить основной набор тестов
bash Scripts/package-dmg.sh            # Упаковать готовое приложение и записать SHA-256
```

Для изолированной сборки используйте `bash Scripts/build.sh .build/candidate`. Упаковщик берёт приложение из `dist/`; перед упаковкой выполните обычную сборку. Подпись ad-hoc, без Developer ID и notarization.

## Стиль и именование

Используйте четыре пробела, `UpperCamelCase` для типов и `lowerCamelCase` для методов и свойств. Следуйте соседнему Swift-коду; файлы называйте по основному типу. Скрипты используют `kebab-case.sh`. Сохраняйте совместимость с режимом Swift 5 и macOS 14. Автоматический форматтер и линтер не настроены.

## Проверки

Тесты — отдельные Swift-программы с `@main` и проверками условий, без XCTest. Используйте имена `<Subject>Tests.swift`; новые проверки подключайте к подходящему скрипту. Для исправления ошибки добавляйте проверку её воспроизведения. Порог покрытия не установлен.

Изменения рендера проверяйте через `bash Scripts/test-renderer-gpu.sh`, жизненного цикла — через `bash Scripts/test-application-lifecycle.sh`. Они требуют активной графической сессии. Замеры производительности выполняйте отдельно от сборок и других графических тестов. Указывайте реальные macOS, оборудование и непроверенные сценарии.

## Коммиты и Pull Request

Используйте короткие английские заголовки коммитов. В PR опишите проблему, новое поведение, связанную задачу и выполненные проверки; для визуальных изменений приложите изображения собственной тестовой сцены.

## Ограничения для агентов

Создавайте коммиты и теги только по явной просьбе. Не редактируйте сгенерированные результаты. Доступ «Универсальный доступ» выдаёт пользователь; диагностируйте геометрию окон без чтения их содержимого.
